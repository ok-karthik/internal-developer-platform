## Decisions already made — do not reopen

1. Links use the monorepo URL, hard-coded in the template (same as the ApplicationSet template).
2. **No `argocd/app-name` annotation.** The real name ends in `-{cluster}`, which the scaffolder
   cannot know, there is one Application per env×cluster, and there is no ArgoCD plugin. Add
   later with `argocd/app-selector` once Applications get labels.
3. **No per-env links** (no `/dev` GitOps link, no service endpoint link): the file is per-service.
   The GitOps link points at the service folder, which lists every env.
4. **Grafana link** goes to `https://grafana.localhost` titled "Grafana (local)" — there is no per-service dashboard to link to.
5. `owner: team-[[ .TenantName ]]` and `lifecycle: production` stay unchanged (see Out of scope).
6. Link `icon`s: only `github` and `dashboard` (standard Backstage system icons). No `git`/`web`.

## Part 1 — Template

Replace the body of `catalog-info.yaml.tmpl` with exactly this (keep `[[ ]]` / `[%`-free Go syntax;
note the `-` trim markers):

```yaml
apiVersion: backstage.io/v1alpha1
kind: Component
metadata:
  name: [[ .AppName ]]
  description: [[ .AppName ]] — [[ .Runtime ]] service for tenant [[ .TenantName ]], delivered by GitOps
  tags:
    - [[ .Runtime ]]
[[- range .Capabilities ]]
    - [[ . ]]
[[- end ]]
  links:
    - url: https://github.com/ok-karthik/internal-developer-platform/tree/main/3-tenant-repos/[[ .TenantName ]]/workloads-repo/services/[[ .AppName ]]
      title: Source
      icon: github
    - url: https://github.com/ok-karthik/internal-developer-platform/tree/main/3-tenant-repos/[[ .TenantName ]]/gitops-repo/services/[[ .AppName ]]
      title: GitOps config (all environments)
      icon: github
    - url: https://grafana.localhost
      title: Grafana (local)
      icon: dashboard
  annotations:
    github.com/project-slug: ok-karthik/internal-developer-platform
    backstage.io/source-location: url:https://github.com/ok-karthik/internal-developer-platform/tree/main/3-tenant-repos/[[ .TenantName ]]/workloads-repo/services/[[ .AppName ]]/
spec:
  type: service
  lifecycle: production
  owner: team-[[ .TenantName ]]
  # System is a Backstage RELATION, not a location — it groups services without
  # dictating a directory level. Omitted when --system is not supplied.
  [[- if .SystemName ]]
  system: [[ .SystemName ]]
  [[- end ]]
```

The `description` contains an em dash and no `:` followed by a space, so it is a valid plain
YAML scalar. If the yaml test in Part 2 says otherwise, quote it — do not change the wording.
